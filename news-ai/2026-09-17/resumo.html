Técnicas e Skills em Alta

  1. Context engineering: desenho deliberado de tudo que o modelo "vê" — instruções, dados recuperados, ferramentas, memória, fatos do usuário, restrições de saída e o que é deliberadamente omitido. Diferente de prompt engineering, é uma disciplina de arquitetura de sistemas de informação (memória, retrieval, priorização, governança de dados).
  2. Function calling / tool use estruturado: definir esquemas de ferramentas corretamente segue sendo a base do desenvolvimento de agentes modernos, já que LLMs de 2026 (Claude Fable 5.1, GPT-6 Astra, Gemini 3.8) invocam APIs e código externo de forma nativa.
  3. Agentic coding "em time": em vez de um único assistente, orquestrar múltiplos agentes especializados com isolamento forte (sandboxing, controle de recursos) — padrão que o OpenHands está popularizando para execução segura de código por agentes.
  4. CodeAct / agentes code-first: em vez de o agente chamar tools via JSON, ele escreve e executa código Python diretamente — abordagem adotada tanto pelo smolagents (Hugging Face) quanto pelas extensões do Microsoft Agent Framework anunciadas no Build 2026.
  5. MCP stateless / tasks assíncronas: adaptar servidores e clientes MCP ao novo modelo de requisições autocontidas e à extensão de tasks assíncronas (fora do core desde a spec 2026-07-28), preparando integrações para escalar sem conexões persistentes.

Papers em Tendência

  • Fine-tuning with RAG for Improving LLM Learning of New Skills (arXiv 2510.01375, ICLR 2026) — extrai "hints" compactos e reutilizáveis a partir de falhas de agentes, gera trajetórias de professor melhoradas via retrieval one-shot no início do episódio, e treina modelos-aluno removendo os hints das trajetórias, forçando internalização em vez de memorização. Generaliza entre escalas de modelo (7B/14B) e arquiteturas de agente (ReAct/StateAct).
  • MemRiskBench: Trace-Aware Risk-Preserving Evaluation for Long-Horizon LLM Agents (arXiv 2609.14976, submetido 14/09/2026) — benchmark para avaliar riscos de memória em agentes de longo horizonte: fatos desatualizados, atualizações conflitantes, vazamento entre usuários, reuso de memória revogada e decaimento de restrições.
  • SoK: Agentic Retrieval-Augmented Generation (RAG): Taxonomy, Architectures, Evaluation, and Research Directions (arXiv 2603.07379) — sistematização (Systematization of Knowledge) do estado da arte em RAG agêntico, cobrindo taxonomia, arquiteturas e direções de avaliação.
  • EvoMemBench: Benchmarking Agent Memory from a Self-Evolving Perspective (arXiv 2605.18421) — compara 15 métodos representativos de memória de agentes contra baselines de contexto longo, concluindo que os sistemas de memória atuais ainda estão longe de uma solução geral.
  • Knowledge Augmented Finetuning Matters in both RAG and Agent Based Dialog Systems (arXiv 2506.22852) — mostra que fine-tuning com aumento de conhecimento traz ganhos tanto em sistemas de diálogo baseados em RAG quanto em agentes, reforçando a tendência de combinar fine-tuning com retrieval em vez de escolher só um.
  • Are We Ready For An Agent-Native Memory System? (arXiv 2606.24775) — questiona se a infraestrutura de memória atual (bancos vetoriais, grafos de conhecimento) foi de fato desenhada para agentes autônomos ou é uma adaptação de sistemas feitos para busca tradicional.
