Técnicas e Skills em Alta

  1. Agentic RAG: em vez de um pipeline de retrieval único, o agente decide iterativamente quando buscar, re-buscar e reformular a query, combinando raciocínio com recuperação de contexto. Analistas de mercado em 2026 apontam que stacks de produção cada vez mais combinam RAG, fine-tuning e agentes em vez de escolher só um.
  2. Fine-tuning com LoRA/QLoRA para modelos pequenos especializados: guias práticos de 2026 recomendam fine-tuning não para "ensinar fatos novos" (isso é papel do RAG), mas para fixar comportamento e estilo em modelos abertos menores, reduzindo custo de inferência em produção.
  3. Auditoria de segurança de "skills" de agentes: com o crescimento de marketplaces de skills (Claude Code, higgsfield-ai/skills), ferramentas como NVIDIA/SkillSpector surgiram para escanear permissões e comportamento de skills de terceiros antes da instalação — resposta direta a vetores de prompt injection via skill malicioso.
  4. Defesa contra prompt injection e output filtering: roadmaps de carreira de 2026 citam isso como gap entre capacidade de IA e maturidade de governança nas empresas — cada vez mais tratado como skill obrigatória, não opcional, para quem constrói agentes expostos a conteúdo externo (ex.: IssueTrojanBench mostrou agentes como Cursor e Claude Code sendo manipulados por instruções maliciosas escondidas em issues do GitHub).
  5. Orquestração multi-agente com chains A2A assíncronas: CrewAI adicionou em 2026 comunicação agent-to-agent nativa com mecanismos de atualização configuráveis (poll/stream/push), reduzindo a necessidade de orquestração manual entre agentes especializados.
  6. MCP como padrão de integração de tools: com a migração para a Linux Foundation e adoção por OpenAI e Google além da Anthropic, expor funcionalidades via servidor MCP (como fez a Qodo com seus agentes de CLI) se tornou o caminho padrão para dar a agentes acesso a ferramentas externas.

Papers em Tendência

  • GenXR-Bench (arXiv 2610.29014, 21/10/2026) — benchmark para agentes de coding construindo aplicações de realidade estendida (XR) interativas; relata falhas recorrentes em lifecycle de sensores e fundamentação física/espacial, mostrando o limite atual de agentes fora do domínio "código de tela".
  • Benchmarking Coding Agents for System-Level Performance Optimization (arXiv 2610.29695, 21/10/2026) — argumenta que benchmarks de coding avaliam majoritariamente no nível de função/repositório; achado principal: a falha mais comum é código correto e dentro das restrições, mas que não melhora a performance real de ponta a ponta.
  • LSCBench (Last Secure Code Benchmark) (arXiv 2610.14766, atualizado 14/10/2026) — mede não só se o código do agente passa testes funcionais, mas se é seguro; o melhor agente avaliado passou 91,3% dos testes funcionais, mas só 25,1% atingiu o critério combinado "funciona e é seguro" — gap relevante para quem usa agentes de coding sem revisão de segurança adicional.
  • IssueTrojanBench (arXiv 2607.20759, jul/2026) — testa se agentes como Cursor e Claude Code podem ser desviados por instruções maliciosas escondidas em issues/PRs do GitHub, relevante para quem conecta agentes a repositórios com colaboradores externos.
  • SWE-Chain (arXiv 2605.14415) — benchmark para agentes de coding em cadeias de upgrade de pacotes em nível de release, avaliando se o agente consegue navegar múltiplas versões e dependências quebradas em sequência.
  • FeatureBench (arXiv 2602.10975) — benchmark de coding agêntico para desenvolvimento de features complexas de ponta a ponta, indo além de bug-fixing isolado para avaliar entrega de funcionalidade completa.
